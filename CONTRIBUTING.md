# Contributing

Read README, UPSTREAM/NOTICES and SECURITY. Both editions are original code using the same in-process core. Keep the baseline runnable and compare identical fixtures before changing Pip styling. Use focused branches/PRs with a concrete behavior change, relevant tests, native evidence where applicable and honest remaining gaps.

Run `swift test --jobs 2`, build both products, then run the affected packaged flow on synthetic content. Add regression coverage for data/citation/privacy invariants. Screenshots show only original app UI and clearly labelled synthetic data. Do not commit personal sources, app-support folders, `.build`, model files, raw reference captures or credentials.

No dependency/weight/network connection should be added without licence/provenance, explicit data boundary, offline/error behavior and tests. Keep official reference names/links for attribution; do not copy proprietary code, assets, branding or reserved animation code. Source content must never become executable instructions.

Describe version, OS/architecture, inputs and reproduction steps in bug reports. Features and parity gaps belong in FUTURE-IDEAS and PARITY; a plan is not runtime evidence.
