# Optional local drafting

**Status: experimental and unaccepted.** The core notebook/evidence workflow works without this feature. Drafting is off by default and sends selected question/passages only to an already-running **local** Ollama process after explicit opt-in. A 24 October production opt-in run with the exact Qwen3 1.7B pin passed one synthetic conflict-and-persistence case and one hostile-source case. Its absent-fact case failed: asked for public-holiday hours, it returned only “The station garden closes at 18:00 on weekdays [1].” It did not explicitly invent holiday hours, but failed to say that the passage contained no holiday information. The conflict output also added misleading interpretation of source/revision dates. Structural validation and one successful persistence case do not establish factual grounding. Earlier Qwen3 0.6B failed attribution/conflict checks; a bounded raw comparison with the existing Qwen3.5 0.8B repeated the missing-support failure and was not adopted. The app never downloads weights, starts a paid provider, uses an account or silently switches to a cloud service.

## Setup

1. Install Ollama from its [official website](https://ollama.com/) and start the local service. Follow its current official instructions and licence.
2. Install the exact supported public model using `ollama pull qwen3:1.7b-q4_K_M` (about 1.4 GB). Check the [model page](https://ollama.com/library/qwen3:1.7b-q4_K_M), its Apache-2.0 [licence layer](https://ollama.com/library/qwen3:1.7b/blobs/d18a5cc71b84) and [artifact provenance](FOUNDATION.md). The inspected local weight blob was 1,359,279,776 bytes (SHA-256 `3d0b790534fe4b79525fc3692950408dca41171676ed7e21db57af5c65ef6ab6`).
3. Check `ollama list`. The app requires manifest fingerprint `8f68893c685c3ddff2aa3fffce2aa60a30bb2da65ca488b61fff134a4d1730e7`. A mutable registry tag may change; if it differs, the app blocks drafting before sending passages. Use evidence mode and review a supported update rather than renaming an arbitrary model to bypass the check.
4. Generation quality remains unaccepted. The 1.7B model passed the synthetic conflict/persistence and hostile-source cases, but failed missing-support handling as described above. Evidence mode and manual notes work independently; do not bypass validation or treat an output as verified evidence.

No remote installer script or global security setting is needed. Ollama is separately installed; it is not bundled in release apps. The 24 October controlled probe used Ollama `0.40.6` on the inspected machine; this is recorded evidence, not a declared minimum supported version. The selected Q4_K_M weight occupies about 1.4 GB before runtime/context memory. Peak memory and latency across devices have not been characterized. Successful fixture tests are not proof of real inference or output quality; TESTING records actual runs separately.

## Boundary and limits

The fixed endpoint is `http://127.0.0.1:11434`; arbitrary remote endpoints are unsupported. Each explicit request first makes a bounded metadata-only `/api/tags` check, then posts the question and exact numbered excerpts to `/api/chat`. Redirects, authentication, cookies, credentials, proxies and tool calls are blocked/unused. The local daemon is trusted as software running under your account; checking its reported fingerprint does not defend against a malicious daemon or a concurrent model replacement.

Maximum input: 2,000 question bytes, 8 citations, 10,000 passage bytes, 14,000 combined system/user bytes. Generation uses a bounded 16K context and 768 output budget, deterministic settings, 5-second metadata + 55-second draft deadlines and a 128 KiB response cap. Large inputs fail explicitly without quietly dropping or renumbering sources. Stop cancels the client request; the separate local daemon controls its own compute cleanup.

The request uses an ordinary JSON-string schema and supplies canonical citation tokens in the prompt; it does not use the prior regex-shaped JSON grammar. The independent response validator remains unchanged and checks JSON shape, nonempty lines, byte bounds and exact supplied `[n]` IDs. The explicit opt-in live suite covers a conflicting two-source answer with persistence, an absent-fact question, and hostile instructions embedded in source text. Run it only when you intend local inference with `PIP_RESEARCH_TEST_LOCAL_DRAFT=1 swift test --filter LocalDraftLiveTests`; otherwise these cases are skipped. These checks do not establish general factual grounding. Sources and questions are untrusted data, not executable instructions. Generated content is displayed as plain text with no tool execution or automatic URL opening. Successfully saved drafts are labelled separately in exports.
